# mini-pi-agent v0.5 — Extensions & Lifecycle Hooks

Status: **active design/implementation snapshot on branch `v0.5`**.

Base: frozen `v0.4.0` Skills snapshot.

Primary mental model:

> **An Extension is trusted executable runtime customization exposed through explicit registrations and lifecycle hooks.**

Important contrast:

```text
Skill      → teaches the model what/how to do
Tool       → executes an environment capability
Extension  → changes runtime behavior at public boundaries
```

And:

```text
EventBus      = what happened?
HookPipeline  = may this happen / should it change?
```

## Target architecture

```text
ExtensionDefinition
        ↓ setup(api)
ExtensionHost
   ├── ExtensionAPI.registerTool()
   ├── ExtensionAPI.on(hook)
   └── owned registrations
        │
        ▼
   HookPipeline
        │
        ├── before_run
        ├── before_model
        ├── after_model
        ├── before_tool
        ├── after_tool
        ├── after_turn
        └── after_run
        │
        ▼
 Agent / AgentLoop lifecycle
```

Extensions receive a narrow `ExtensionAPI`, never the concrete mutable Agent object.

## Deterministic ordering

```text
load Extension A
load Extension B

A registers A1, A2
B registers B1

hook execution:
A1 → A2 → B1
```

No priority numbers in v0.5.

## Initial transformation model

`before_tool` is the strongest first hook:

```ts
type BeforeToolDecision =
  | { action: "continue" }
  | { action: "replace"; arguments: Record<string, JsonValue> }
  | { action: "block"; reason: string };
```

Handlers compose sequentially. A replacement becomes input to the next handler. A block stops the pipeline and becomes an explicit failed ToolResult rather than silently disappearing.

`before_model` may contribute budget-accounted `ContextSupplement`s. It must not append arbitrary prompt text after planning.

`after_model`, `after_turn`, and `after_run` begin as observational/cleanup hooks; replacement of AssistantMessage is intentionally out of scope.

## Registration ownership

Every registration records the owning Extension so unload can remove exactly that Extension's:

```text
hooks
tools
context contributors
```

This version does not implement a package marketplace or hot reload, but ownership semantics are established now so future reload does not accumulate stale registrations.

## Failure policy

```text
intercepting hook throws
→ ExtensionHookError
→ current operation/run fails visibly

cleanup/observational hook throws
→ recorded as extension error
→ remaining cleanup continues where safe
```

Every async hook receives the active `AbortSignal`.
