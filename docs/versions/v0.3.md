# v0.3 — Context Budget & Compaction

Status: **implemented historical snapshot on branch `v0.3`**.

Root `version.md` is the exact branch acceptance/freeze contract. `Plan.md` remains the repository-wide roadmap. This document records the design model that the v0.3 implementation now realizes.

---

# 1. Problem

Long-running agents accumulate:

```text
user requests
assistant output
tool calls/results
large logs/files
errors/retries
follow-up turns
```

Resending the complete lifetime history forever increases token cost/latency and eventually exceeds model context limits.

The wrong fixes are:

```text
delete durable history
blindly keep last N messages
silently truncate tool output
summarize the entire lifetime every turn
add a vector DB before defining context lifecycle
```

v0.3 instead separates historical truth from model-visible projections.

---

# 2. Fundamental separation

```text
Runtime State
≠
Durable Session History
≠
Prepared Model Context
≠
Summary Checkpoint
```

Durable history remains complete. Model context and summaries are derived artifacts.

---

# 3. Implemented architecture

```text
Durable AgentMessage[]
      │
      ├────────────► SessionStore
      │
      ├── ContextUnitBuilder
      │       ↓
      │   ToolResultReducer
      │       ↓
      │   KeepRecentContextPlanner
      │       ↓
      │   PreparedContext
      │
      └── old prefix
              ↓
      ProgressiveSummaryPolicy
              │
              ├── previous ContextSummary
              ├── newly covered messages
              └── ContextSummarizer
              ↓
         SummaryStore

ContextRuntime
      │
      ├── reads latest checkpoint
      ├── renders checkpoint as model-only system context
      ├── plans the remaining durable tail
      ├── advances checkpoint when needed
      └── re-plans until stable
      ↓
PreparedContext
      ↓
AgentLoop
      ↓
LLMProvider
```

```text
inputBudget

```

Provider-specific tokenizers can replace the estimator later without changing planning policy.

# 5. Causal context units

A tool exchange is modeled as one causal unit:

```text
AssistantMessage(toolCalls)
+
matching ToolResultMessage[]
=
ToolExchangeContextUnit
```

The builder detects orphan/duplicate/mismatched tool history and supports an explicitly incomplete trailing exchange for durable recovery state.

A prepared provider context or summary coverage boundary must not silently cut a complete exchange.

---

# 6. Large ToolResult projection

Reference reducer:

```ts
HeadTailToolResultReducer
```

Default policy:

```text
thresholdChars = 20,000
headChars      =  8,000
tailChars      =  8,000
```

The full durable ToolResult remains unchanged. The model-visible copy contains explicit reduction metadata plus head/tail content.

---

# 7. KeepRecent planner

`KeepRecentContextPlanner`:

```text
build complete ContextUnits
      ↓
reduce large ToolResults in copies
      ↓
estimate units
      ↓
walk newest → oldest
      ↓
select one contiguous recent suffix
      ↓
restore chronological order
      ↓
PreparedContext
```

Reference priority:

```text
recent temporal continuity
>
maximum packing density
```

Impossible budgets fail explicitly.

---

# 8. Summary checkpoints

Implemented checkpoint:

```ts
interface ContextSummary {
  id: string;
  content: string;
  coversThroughMessageIndex: number;
  estimatedTokens: number;
  createdAt: number;
}
```

Coverage means:

```text
coversThroughMessageIndex = N
→ summary represents durable prefix history[0..N]
```

`SummaryStore` is separate from `SessionStore` because summaries are derived/regenerable state rather than conversational truth.

---

# 9. Progressive summarization

```text
history[0..100] → S1
S1 + history[101..170] → S2
S2 + history[171..240] → S3
```

`ProgressiveSummaryPolicy` owns coverage/commit semantics. `ContextSummarizer` owns content generation only.

Reference offline implementation:

```ts
DeterministicContextSummarizer
```

Important rules:

- coverage only stays equal or advances;
- target boundaries must end complete ContextUnits;
- same-boundary requests are no-ops;
- failed/cancelled generation does not commit a new checkpoint;
- durable history is never modified.

---

# 10. Runtime composition

The final v0.3 integration introduces:

```ts
ContextRuntime
```

It deliberately keeps the compaction loop outside `runAgentLoop()`.

Conceptually:

```text
load summary
   ↓
plan unsummarized tail
   ↓
older unsummarized units omitted?
   ├── no  → return PreparedContext
   └── yes → advance summary through omitted complete prefix
                  ↓
               re-plan
```

The process is bounded by `maxSummaryPasses`.

---

# 11. Summary visibility

A summary checkpoint is not inserted into `AgentMessage[]`.

Instead:

```text
base system prompt
+
[mini-pi-agent context checkpoint]
...
[/mini-pi-agent context checkpoint]
+
recent durable messages
```

becomes the model request.

Thus:

```text
state.messages       = full durable history
SessionStore         = full durable history
SummaryStore         = derived checkpoint
LLMRequest.messages  = recent prepared tail
LLMRequest.system    = base system + checkpoint context
```

---

# 12. Lifecycle events

Implemented:

```text
context_prepare_start
context_summary_advanced
context_prepared
```

Events expose metadata/counts rather than dumping complete private model context.

# 13. Backward compatibility

`AgentOptions.context` enables the v0.3 runtime.

The older `contextTransform` seam remains available for educational/backward compatibility when `context` is not configured.

The two are mutually exclusive.

---

# 14. Acceptance properties

v0.3 is complete when the reader can demonstrate:

```text
planning does not mutate durable history
visible tool calls preserve corresponding observations
large tool observations reduce explicitly
context stays within budget or fails explicitly
summary coverage has explicit provenance
progressive summary only consumes newly old history
abort/failure before commit preserves previous checkpoint
Agent sends compacted context while SessionStore stays complete
```

The implementation and test sources now encode these properties.
